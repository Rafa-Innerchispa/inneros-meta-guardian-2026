## 1. Executive Summary: The Premature Mutation Flaw

During the independent verification of candidate code repairs, a **Critical Safety Flaw** was discovered in the patch generated by the sovereign model **Local Qwen3-Coder-30B-AWQ** (`docs/evidence/bench_20261104/patches/qwen_local_repair.py`).

The candidate attempted to enforce all required safety invariants, but placed the database mutation **prior** to the worker heartbeat check. In a production cluster with active workers, this flaw would cause **active tasks to be stolen, mutated, or corrupted** while a worker is still healthy and processing.

---

## 2. Anatomy of the Vulnerability (CVE-Equivalent Severity)

### Code Snippet from `qwen_local_repair.py` (Lines 53–78):

```python
    # 4. Enforce atomic CAS
    result = db_collection.update_one({
        "_id": task_id,
        "revision": revision,
        "status": {"$in": ["awaiting_antigravity_claim", "awaiting_cursor_claim"]}
    }, {
        "$set": {
            "status": "awaiting_claim",
            "lease_until": time.time() + 300,
            "revision": revision + 1
        }
    })

    if result.modified_count != 1:
        return False

    # 5. Skip if active heartbeat or PID  <-- CRITICAL FLAW!
    if heartbeat and time.time() - heartbeat < 180:
        return False
    if pid is not None:
        try:
            os.kill(pid, 0)
            return False
        except OSError:
            pass

    return True
```

### Failure Mode & Impact:
1. **Precondition Inversion:** In any distributed state machine or lock recovery mechanism, **all liveness and safety preconditions must be verified before modifying state**.
2. **State Pollution on Rejection:** If a task had an active heartbeat (e.g., received 15 seconds ago), `update_one` **already modified the document in MongoDB** (incrementing the revision, changing its lease, or resetting its status) before line 70 evaluated `if heartbeat and time.time() - heartbeat < 180: return False`.
3. **Split-Brain Risk:** Although the function returns `False`, the active worker holding the task will experience lease rejection or revision mismatch on its next cycle, resulting in split-brain task abandonment.

## 3. Corrective Action & Verification (`qwen_repaired_v2.py`)

A remediated candidate was created in `docs/evidence/bench_20261104/patches/qwen_repaired_v2.py` strictly enforcing:

1. **Pre-Mutation Invariant Pipeline:**
   - Worker heartbeat (< 180s) is parsed and validated first.
   - Cross-host provenance is evaluated; if on remote host `ralphi-ia-ver-10`, `os.kill` is prohibited and `remote_liveness_verifier` is enforced.
   - Local OS process liveness is checked via `os.kill(pid, 0)` with safe exception handling.
   - Worktree linked `.git` pointer files (`gitdir: ...`) are fully resolved to detect active `index.lock` locks.
2. **Atomic CAS with Zero Writes on Abort:**
   - If any precondition indicates the worker is active or locked, the loop immediately continues to the next candidate with **zero writes** to MongoDB.
   - Database mutation uses an atomic CAS filter matching `task_id`, `status: claimed`, `claim_token`, `lease_until`, and `revision`, returning only when `modified_count == 1`.

## 5. Security Conclusion for Production Deployment

Autonomous code generators frequently produce logically plausible code that violates distributed systems safety ordering (such as placing side-effects before assertion guards). 

**Production Rule for InnerOS:** No LLM-generated self-healing patch may be applied to production without passing:
1. Static AST analysis confirming mutation calls occur strictly after all precondition guard clauses.
2. The complete regression suite in an isolated ephemeral worktree.
3. Explicit human owner sign-off.
